# 서류 작성 도우미 (본인 작성 보조)

기관이 공개한 **빈 신청 양식**을 이용자가 앱 안에서 직접 채우고, 파일로 저장·공유한 뒤 **기관에 직접 제출**하는 기능이다. 마지미는 대리 작성·제출을 하지 않는다. 무료 기능이며 금융상품 신청서는 대상이 아니다.

## 1. 양식 형식별 처리 (실측 근거)

2026-10-11 공개 양식 7건을 `scripts/forms/inspect-template.mjs`로 검사했다(파일은 로컬 임시 폴더에서만 검사, 저장소에 넣지 않음).

| 출처 | 형식 | AcroForm 입력 칸 |
|---|---|---|
| suncheon.go.kr `…/FILE_000001000073751/2026022511135182387` (2026 전남 청년 근속장려금 신청서 서식) | PDF 4쪽 | 없음 |
| jeonju.go.kr `…/original/ba479d92-ef1e-4f97-a3c4-5b5d70c74531.pdf` (공모 신청 서식) | PDF 7쪽 | 없음 |
| arts.gunsan.go.kr `…/eFileDownload/335/1007566/92f74aa7…` (청년공동체활동지원사업 신청서식) | HWP | 해당 없음 |
| arts.gunsan.go.kr `…/eFileDownload/335/1105116/7041f51a…` (지역청년활동가 공고문) | HWP | 해당 없음 |
| tour.gunsan.go.kr `…/eFileDownload/7/1276217/02b98e43…` (전북형 청년취업지원사업 모집공고) | HWP | 해당 없음 |
| studyinkorea.go.kr `…/gks_graduate_user_guide.pdf` (안내서) | PDF 57쪽 | 없음 |
| ttgu.ac.kr 교외 자격 장학금 신청서 (대학, 참고용) | PDF 1쪽 | 없음 |

결론: 공공 양식은 **HWP이거나 입력 칸 없는 PDF**가 대부분이다. AcroForm 채우기만으로는 거의 쓸 수 없으므로, 관리자가 PDF 위에 입력 칸을 한 번 그려 두는 **템플릿 방식**을 PDF의 기본 경로로 둔다.

| 형식 | 처리 |
|---|---|
| PDF + 관리자 템플릿(같은 파일 해시·같은 쪽수) | 문서 위 입력 칸 채우기(overlay) |
| PDF + 자체 AcroForm 입력 칸 | 입력 칸을 overlay 필드로 가져와 같은 화면에서 채우기 |
| 입력 칸 없는 PDF, 암호·XFA·회전 PDF, 웹 | 안내형 복사 시트 + 원본 양식 열기 |
| HWP / HWPX / DOCX | 안내형 복사 시트 + 원본 양식 열기 (관리자가 공식 PDF 판을 자료로 등록하면 PDF 경로) |

## 2. 흐름

1. 신청 도우미·공고 상세의 `ApplicationResourcesCard` → "서류 작성 도우미로 채우기" (`/form-fill?programId&resourceId`).
2. 공고를 다시 조회해 자료가 아직 공개·유효한지 확인(`currentResource`). 금융상품이면 중단.
3. 검증된 URL(HTTPS·공개 호스트)에서 양식을 내려받고, **서버가 기록한 크기·SHA-256과 다르면 사용하지 않는다**. 캐시 파일은 읽은 즉시 삭제.
4. 템플릿 결정: 관리자 템플릿 → AcroForm 가져오기 → 안내형 시트.
5. 문서 화면: pdf.js(WebView)로 그린 쪽 이미지 위에 입력 칸. 칸을 누르면 입력 시트. 목록 보기는 접근성 대안이자 미리보기 실패 시 기본값.
6. 안내 이동: "필수 항목 N개 남음 · 확인 필요 M개", 진행 막대, 이전/다음 항목(다음 미완료 칸으로 스크롤), "해당 없음".
7. 칸 종류: 한 줄·여러 줄 글자, 날짜(양식별 표기 `YYYY.MM.DD` 등, 오늘 버튼), 체크, 손글씨 서명, 이름 도장.
8. 작성 완료 → 기기에서 PDF에 평면화(입력 위젯 제거, NanumGothic 전체 임베드) → 모든 쪽 미리보기와 입력 내용 요약 → "직접 확인했고 제출은 직접 한다" 체크 → 시스템 공유·저장.
9. 내보낸 뒤: 주민등록번호·계좌번호를 메모리에서 지우고, 기기 작성 기록(일시·사업·양식 이름·양식 해시, 값 없음)을 남긴다.

## 3. 개인정보·법적 안전장치

- 제안값(프로필 학교명·학년, 오늘 날짜, 선택 시 기기에 기억한 성명·연락처·주소·이메일)은 `suggested` 상태로만 들어가며, 확인하거나 고치기 전에는 완료할 수 없다. 별명은 성명으로 쓰지 않는다.
- 주민등록번호·계좌번호: 제안·기억 대상이 아니며 작성 중 메모리에만 있다. 내보낸 직후와 화면 이탈 시 사라진다. 기억 저장은 화이트리스트 4개 항목만, RRN 모양·12자리 이상 숫자열은 거절.
- 보호자·부모·대리인 등 본인 아닌 사람의 칸에는 제안값을 넣지 않는다. 라벨이나 연결 정보 중 하나라도 주민등록번호·계좌번호면 민감 칸으로 다룬다.
- 작성 화면은 화면 캡처·녹화를 막고(iOS 앱 전환기 흐림 포함), 민감 칸 입력은 가려서 보여 준다. 앱 시작·회원 탈퇴 시 남은 임시 작성본을 지운다.
- 금융상품 신청서는 앱과 서버(공개 조회·관리자 저장) 양쪽에서 제외한다.
- 서버에는 칸 위치·종류·연결 정보만 있다(`application_form_templates`, service-only RLS, 값 필드 거절). 작성 값·작성본은 서버로 가지 않는다.
- 미리보기 WebView: pdf.js 3.11.174 고정 + SRI, CSP로 jsDelivr 외 요청 차단, 외부 이동 차단. 양식·값은 배포망에 보내지 않는다.
- 문구는 "본인 작성 보조"이며 "자동 신청/대리 작성"을 쓰지 않는다. 개인정보처리방침 제6조의2, 이용약관 제5조에 반영.

## 4. 관리자 템플릿 설계 (admin web)

`/admin/programs/{id}` → 제출 양식(PDF, 수집기 확인 완료) 카드 → "서류 작성 도우미 입력 칸 설계".
관리자가 받은 원본 PDF를 선택하면 브라우저에서 SHA-256을 계산해 검토된 `content_hash`와 다르면 거절한다. 쪽 위를 끌어 칸을 만들고 이름·종류·연결 정보·필수·날짜 표기·글자 크기를 정한다. 방향키로 미세 이동, Delete로 삭제. AcroForm 위젯은 "양식 입력 칸 가져오기"로 시작점으로 쓸 수 있다. 저장은 낙관적 잠금(revision)이다. 기관이 파일을 바꾸면 정의는 `stale`로 표시되고 앱에 제공되지 않는다.

API: `GET/PUT/DELETE /api/v1/admin/application-resources/{id}/form-template`(관리자), `GET /api/v1/programs/{id}/application-resources/{resource_id}/form-template`(공개, 현재 공개 중이고 해시가 같은 PDF 양식만).

## 5. 한계

- 실제 기기·시뮬레이터 실행은 하지 않았다. 검증: 타입 검사, 노드 단위 테스트, RN 0.81 Hermes VM에서 핵심 평면화 실행, 크롬에서 렌더러 HTML 실행, 웹 내보내기 브라우저 재생, 로컬 API·관리자 웹 E2E.
- 작성본 PDF에 글꼴 전체(약 0.75MB)가 들어간다. fontkit 부분 임베드가 NanumGothic 한글(복합 글리프)을 비워서다.
- 미리보기는 공개 배포망에서 pdf.js를 받으므로 오프라인이면 목록 보기로만 작성한다(작성본 생성은 가능).
- 회전 쪽 PDF, XFA, 암호 PDF는 안내형으로 처리한다. 라디오 그룹은 선택지별 체크 칸으로 가져오고 같은 그룹은 하나만 체크되며, 그룹 필수 여부는 강제하지 않는다.
- pdf.js 3.11.174는 CVE-2024-4367 대상이며 `isEvalSupported: false`로 막아 둔 상태다. 앱 번들에 pdf.js를 넣고 CSP의 외부 허용을 없애거나 4.2.67 이상으로 올리는 것이 다음 단계다.
- 화면 캡처 차단(`expo-screen-capture`)은 네이티브 모듈이라 새 개발·스토어 빌드가 필요하다.
- 이름 도장은 간이 이미지이며 인감 등 등록 도장을 대신하지 않는다. 손글씨 서명의 법적 효력은 제출 기관 기준을 따른다.
- 관리자 AcroForm 가져오기는 pdf.js가 위젯에서 읽는 이름을 쓰므로 앱 쪽(pdf-lib, 필드 TU) 이름과 다를 수 있다. 저장 전 이름을 확인한다.
