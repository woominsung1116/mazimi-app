## 원본 값을 읽는 방법

- `tools/design/figma-source.mjs`는 .fig를 refig의 REST 변환이 아닌 Kiwi 노드 단계에서 읽습니다. REST 변환은 한쪽 선(탭 밑줄 2px, 카드 상단 구분선)을 네 변 테두리로 바꾸고 자동 레이아웃(간격·여백)을 버립니다.
- 변수에 연결된 색은 변수 값으로 풀어 씁니다. 파일 안 색 스냅샷은 오래된 값일 수 있습니다. 예: 동의 체크는 스냅샷 `#F5C15F`, 실제 변수는 Primary `#34BB84`. 정렬 화살표는 스냅샷 주황, 실제는 Primary.
- `docs/design/figma-source/`와 비교 이미지의 왼쪽은 refig 렌더라 위 두 문제를 그대로 보입니다. 값의 기준은 노드와 변수입니다.

## 토큰 한 곳

- `apps/mobile/constants/theme.ts`의 `fig`가 이 값을 Figma 변수 이름으로 담습니다. 예전 이름(`colors.*`, `typography.*`)은 모두 같은 값을 가리킵니다.

## 실제 서비스에 맞춰 남긴 차이

- 2026-10-01 문서의 유지 항목(실제 데이터, 없는 로그인 버튼 미추가, 동의 범위 등)은 그대로입니다. 홈·카드 문구도 사실이 아닌 예시(지원금 최대 340만원, 충족·구비, 커피 이벤트, Lorem Ipsum)로 바꾸지 않았습니다. 구글 로그인은 비활성 그대로입니다.
- 카드 서류 상태 칸은 "공고 확인"입니다. 서류 구비 여부는 아직 알 수 없어 지어내지 않습니다.
- "자격 충족만 보기"는 문구 규칙(충족 단정 금지) 때문에 "조건 확인됨만 보기"로 씁니다. 조건이 확인된 카드만 남기는 실제 필터이고 맞춤 추천 화면에만 있습니다. 탐색 목록에는 확인된 카드가 없어 두지 않았습니다.
- 맞춤 추천 화면은 프레임대로 탭과 개수 줄로 시작합니다. 2026-10-31 정리에서 제외 요약 카드("제외한 이유 보기"), 자격·중복·수령액 안내 줄, "내 조건 수정" 링크, 카드 아래 자동 점검 줄을 뺐습니다. "조건 확인됨만 보기"는 서버가 조건 확인 구역을 켤 때만 보이고, 걸러서 비면 "조건 확인됨 혜택이 아직 없어요 · 전체 보기"를 보입니다.
- 같은 정리(2026-10-31)에서 프레임에 없는 안내·보조 링크를 모두 뺐습니다: 상세의 "최종 조건은 공식 공고에서 확인해 주세요 · 공식 공고 보기"(공식 링크는 혜택 요약 시트에 남음), 기업혜택 지원 정보 제목의 안내, 청년 적합도 줄과 두 번째 배지, 카드 본문에 만들어 넣던 조건 문장("확인된 조건: …")과 기본 문구, 부제의 "공식 혜택"(본문은 공고 요약이 있을 때만, 부제는 기관을 알 때만 보임), 관심 혜택의 "신청 이력 보기"(마이페이지에서 열림), 홈 탭 아래 설명 줄, 비서·도우미·신청 도우미·보관함의 고정 안내 문구, 진입점이 없던 `/calculator`·`/region-compare`. 다시 들어오지 않게 `apps/mobile/scripts/check-user-visible.cjs`가 막습니다.
- 상세 신청 준비 자료 카드는 유지합니다. 사진 위 흐림 막은 없습니다(흐림은 웹·기기 모두 같게 그릴 수 없어 뺐습니다). 같은 이유로 스크롤한 상세 위에 뜨는 헤더(`34065:11165`, White 92% + 배경 흐림 8)는 흐림 없는 92%로 그리면 아래 글자가 비치므로 불투명 White(`fig.component.floatingHeader`)로 그립니다.
- 프레임에 있으나 동작이 없는 것은 넣지 않았습니다: 고객 센터 문의하기(연락 창구 없음), 서류 보관함 검색, 탐색 소득 필터(소득 데이터 없음), 알림 "모두 읽음", 30일 보관 안내, 관심 해제 확인 팝업, 신청 이력 상태 탭.
- 슬라이더는 눈금 탭으로 고르고 끌기는 없습니다. 화면 읽기 프로그램은 한 칸씩 조절합니다.
- Figma 세트에 없는 아이콘은 가장 가까운 Figma 아이콘으로 바꿨습니다: 잠금은 eye-off, 구급상자는 document, 더하기는 45도 돌린 close.
- 새 캐러셀 장의 문구(예: "마지미 비서 무엇을 맡길까요?")는 프레임에 없어 기존 기능 설명에서 가져왔습니다.
- 약관은 Figma의 시트 대신 기존 전체 화면을 유지합니다. Figma의 D-4 배지(34065:6204)는 Orange지만, 앱은 마감 색 규칙(`lib/deadline.ts`의 `URGENT_DAYS = 2`)대로 D-2부터만 강조색을 써서 D-4 배지는 Primary입니다. 타일 바탕색은 Figma와 같습니다. 비활성 버튼 색도 Figma 값입니다.

## 재발 방지

- `npm run test:figma-tokens --prefix apps/mobile`: 앱 코드의 모든 색(투명도 포함)·글자 크기·굵기·줄 높이·글자 스타일 조합이 .fig 값인지 확인합니다. 숫자·토큰·변수 어느 형태로 쓴 글자 크기든 줄 높이가 없으면 실패합니다. 테마 펼침(`...T.body13`)과 토큰을 풀어 읽고, `style={[a, b]}`처럼 여러 블록을 합친 스타일도 .fig 글자 스타일인지 봅니다. 크기·줄 높이·모서리를 변수나 계산식으로 쓰면(토큰 제외) 실패합니다. .fig에 없는 선 두께(hairline, 계산식, 변수 포함), 점선, .fig에 없는 모서리(원은 허용), 아이콘 라이브러리, 글리프(×, • 포함)·이모지·"+ 라벨"도 막습니다. 목록 점은 `BulletRow`가 그립니다. 각 검사는 일부러 틀린 예시(probe)를 함께 돌려, 검사가 그 예시를 잡지 못하면 실패합니다. 테마 토큰이 Figma 노드와 같은지도 확인합니다.
- `npm run check:tokens --prefix tools/design`: `figma-tokens.json`이 .fig와 같은지 확인합니다.
- `npm run check:figma --prefix tools/design`: 웹 export에서 카드·탭·필터·헤더·탭 바·입력·버튼·상세 단계·토글의 계산된 스타일을 노드 값과 비교하고, 탭이 다섯 개인지, 상세 404의 뒤로 버튼이 보이는지, 마이페이지 줄이 44px인지 봅니다. 알림·신청 이력·서류 보관함은 채운 데이터로 그립니다. 390px 화면과 Figma 프레임 비교 이미지를 [validation/figma-restore](validation/figma-restore/)에 저장합니다.
- `tools/design/check-ui.mjs`: 실제 앱 흐름을 따라갑니다. 비회원은 로그인 화면에서 바로 탭으로 가고, 온보딩은 조건이 없는 회원이 홈에서 맞춤 혜택을 누를 때 열립니다.
- CI 모바일 작업이 위 검사를 모두 실행합니다.
