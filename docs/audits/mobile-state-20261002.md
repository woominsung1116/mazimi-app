## 실행한 검증

다음 명령은 변경 후 모두 종료 코드 0으로 통과했다.

```sh
cd apps/mobile
npx tsc --noEmit
npm run test:session
```

추가로 `git diff --check -- apps/mobile tools/design/check-ui.mjs`, `node --check tools/design/check-ui.mjs`를 통과했다.

`scripts/check-session.cjs`는 실제 `store/auth.ts`, `lib/api.ts`, `lib/tokenStorage.ts`를 TypeScript로 변환해 실행한다. HTTP와 저장소만 가짜 구현으로 바꾸며 외부 네트워크와 실제 인증 정보는 사용하지 않는다. 11개 회귀 사례는 다음과 같다.

1. 동시에 발생한 API 401 세 건이 refresh 교환 한 번을 공유한다.
2. refresh 후 403이 원래 상태와 세션을 유지한다.
3. refresh 후 404가 원래 상태와 세션을 유지한다.
4. refresh 후 503이 원래 상태와 세션을 유지한다.
5. refresh 서버의 일시 장애가 세션과 개인 조건을 삭제하지 않는다.
6. 거절된 refresh는 로그아웃하고 신청 이어쓰기 의도를 삭제한다.
7. 로그아웃 뒤 도착한 refresh가 메모리·저장소 세션을 복원하지 않는다.
8. 이전 계정의 지연 401이 새 계정을 refresh하거나 로그아웃시키지 않는다.
9. 시작 시 서버 503이 저장 자격 증명을 삭제하지 않는다.
10. 무효한 저장 세션은 개인 초안과 신청 이어쓰기 의도를 정리한다.
11. 신청이력 404는 서버 오류 문구와 무관하게 아직 신청하지 않은 상태로 반환한다.
