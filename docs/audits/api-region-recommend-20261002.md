신규 회귀가 확인하는 동작:

1. 부산·부산광역시·BUSAN은 같은 추천을 반환한다. 부산 결과는 용인/경기와 미확정 지역을 제외하고 부산·전국 혜택을 유지한다. 1개씩 페이지를 이동해 목록·총수·다음 페이지 여부가 일치함을 확인한다.
2. 학교 미선택·타 대학은 교내 혜택을 받지 않는다. 정확한 대학 이름과 별칭은 같은 대학으로 확인되며, 별도 자격 규칙이 없어도 휴학생 제외 조건을 적용한다.
3. 닉네임 저장과 기존 클라이언트의 닉네임 보존을 확인한다. 잘못된 지역·미래 생년·잘못된 닉네임 요청은 저장된 지역을 바꾸지 않는다.
4. 인앱 설정을 껐다 켜도 기존 인앱 항목은 유지되고 푸시 전용 항목은 목록에 나타나지 않는다. 두 발송 이력은 DB에 계속 남는다.

## 남은 경계와 배포 순서

- migration 19가 API 배포보다 먼저 적용되어야 한다. 새 알림 조회는 `in_app_visible` 컬럼을 사용한다.
- 지역 필터는 시·도 단위다. 같은 도 안의 시·군·구 제한이나 부모 거주·학교 소재지 등 복합 조건은 추가 자격 확인이 필요하다.
- 명시적인 전국 범위는 빈 배열, 미확정 범위는 `['unknown']`이다. 기존 NULL 지역은 호환을 위해 전국 취급을 유지한다. 정규화하지 않은 과거 소스의 NULL이 실제 전국 범위를 증명하는 것은 아니다.
- 미확정 지역은 내 지역·추천에서 제외되지만 전체 탐색에서는 확인할 수 있다. 자동 분류가 확신하지 못한 값을 전국으로 바꾸면 안 된다.
- 대학 선택은 사용자가 신고한 정보이며 재학 인증이 아니다. 학교 미선택 차단과 최종 기관 자격 검증은 서로 다른 단계다.
- 과거 알림은 migration 기본값으로 기존 표시를 유지한다. 과거 발송 시점에 인앱 수신을 거부했는지는 기존 데이터만으로 복원하지 않았다.
- 푸시 토큰 형식 검사는 실제 디바이스 도달 여부를 보증하지 않는다. 전송 응답·폐기된 토큰·재시도 정책은 워커 감사 범위다.

## 워커 지역 정규화 읽기 검토

API/core 동결 후 `crates/worker/src/regions.rs`를 독립적으로 읽었다. 이 검토에서는 워커 코드를 직접 수정하지 않았다.

확인한 방어: 온통청년의 `zipCd`를 법정구역 코드로 취급하며 다른 시·도 및 미인식 코드가 전국으로 바뀌지 않는다. `경기도 광주시`는 경기로 분류한다. 장학금의 지역거주 필드가 없으면 미확정이다. `12` 코드의 최신 행정구역 사전은 메인 에이전트의 원천 확인을 사용했고 이 감사에서 별도로 재조회하지 않았다.

메인 에이전트에 전달했고 후속 코드에서 수정된 사항:

1. 검토 당시 `government()`는 소관기관 유형이 중앙행정기관이면 무조건 전국 배열을 반환했다. 수정 후 지원대상·선정기준에서 거주·소재·관내·주소지·주민등록·전입·출신·해당 지역 조건을 발견하면 미확정으로 처리한다. 중앙기관의 용인 거주 제한 회귀 사례를 추가했다.
2. 검토 당시 `scholarship()`은 자유서술의 선행 시·도명으로 분류했다. 수정 후 정확한 시·도명만 지역으로 인정하고, 명시적인 제한 없음 표현만 전국으로 인정한다. 나머지 자유서술은 미확정으로 남긴다. 복수 지역·미거주자·부모 출신지 사례를 추가했다.

후속 변경은 읽기로 확인했고 워커 회귀 실행 결과는 메인 에이전트의 전체 검증에 포함한다. 위의 42개는 이 API 감사에서 직접 실행한 테스트 수다. 남는 경계는 자유서술의 완전한 해석이다. 중앙기관 조건의 탐지는 현재 필드·키워드에 한정되므로 새로운 표현이나 원천 필드 변경까지 검증한 것은 아니다. 장학금의 복합 조건은 추측해 지역을 넓히지 않고 미확정 상태로 보존한다.

## 후속: 빈 데이터베이스에서의 CI 실패 수정

커밋 `66cb68f`의 [GitHub Actions 실행 36957787059](https://github.com/woominsung1116/mazimi/actions/runs/36957787059)에서 Rust 테스트가 실패했다. 실패 로그를 확인한 결과 Rust 버전 문제가 아니라 테스트 초기화 순서 문제였다.

- `data_maintenance::tests::residence_incident_opens_with_counts_and_resolves_without_deleting_history`: `programs` 테이블 없음, PostgreSQL `42P01`.
- `sources::benefit_pages::tests::transient_access_preserves_approval_but_robots_disallow_revokes_it`: `benefit_source_domains` 테이블 없음, PostgreSQL `42P01`.

워커 라이브러리 테스트는 스키마가 준비된 DB를 사용한다. 이전 CI는 빈 PostgreSQL에서 라이브러리 테스트부터 실행했고 마이그레이션은 나중의 API 통합 테스트에서만 실행됐다. 스키마가 이미 있던 로컬 DB에서는 이 문제가 드러나지 않았다.

`.github/workflows/ci.yml`을 다음과 같이 수정했다. 런타임 코드는 이 CI 수정에 포함하지 않았다.

1. 테스트 잡의 `DATABASE_URL`과 `TEST_DATABASE_URL`을 같은 격리 PostgreSQL로 명시한다.
2. 모든 테스트 전에 기존 `api-migrate` 실행 파일로 마이그레이션을 적용한다.
3. `--lib`, `--bins`, `--test '*'`를 순서대로 실행한다. 워커 실행 파일 안의 알림 회귀 6개도 CI 대상에 포함한다.
4. 통합 테스트의 `continue-on-error: true`를 제거한다. 통합 테스트 실패가 성공한 검사로 처리되지 않도록 한다.

새로 생성한 빈 로컬 DB에서 마이그레이션 성공 후 라이브러리 185개(26 + 33 + 126, 기존 외부 연동 1개 제외)와 통합 93개, 총 278개가 통과했다. YAML 파싱과 변경 파일의 `git diff --check`도 통과했다. 실행 파일 테스트 6개는 앞선 전체 검증에서 통과한 대상이며, 후속 백필 코드 작업이 완료된 뒤 메인 에이전트가 최종 전체 검증을 다시 수행한다. 이 절에서 직접 확인한 범위는 빈 DB 마이그레이션과 278개 테스트다.

수정된 워크플로의 원격 성공 여부는 후속 커밋의 GitHub Actions 결과로 별도 확인해야 한다.

### CI 컴파일러 재현성

GitHub의 부동 `stable`이 Rust 1.99를 설치해 `async-trait`가 생성한 코드에 `double_must_use` 경고를 발생시켰다. 운영 API/워커 Docker와 로컬 검증은 Rust 1.94.0을 사용한다. CI도 1.94.0을 명시해 동일한 버전으로 검사한다. 경고 무시 설정은 추가하지 않았으며 도구 버전 업그레이드는 운영 이미지와 CI를 함께 검증해야 한다.
